dgem

Templates, readout, calibration and routing for a zero-shot decision engine on DiffusionGemma.

dgem takes some text or an image, which we call the state, and a list of typed questions from a template file. For each question it returns the answer it picked, the probability of every allowed answer, and an uncertainty score. It answers up to ten questions at once on a shared canvas. A whole form costs one forward pass and about 125 milliseconds on one GPU. We do not change the model weights. Instead, dgem fixes the model's raw probabilities at request time so they match how often the model is right, and sends hard cases to Gemini when the evidence is split.

This page explains what you can build with dgem, how DiffusionGemma reads a canvas of answer slots, why raw single-pass probabilities fail, how our calibration steps fix them with zero extra GPU passes, and how the system scores across 13 experiments. The full record is in dgem_benchmark_briefing.html; the receipts are in docs/experiments/README.md.

01

What you can build

You supply a state, which is the text, JSON record, or image to judge, and a template file that lists the questions. Each question has a type. A noul question is a yes or no check. A choice question picks one option from up to 255 named choices, each with its own criteria. A score question picks an ordered level (such as 0 to 3) and returns the probability-weighted average. For every question you get back the chosen answer, the probability of each option, the entropy score, and an escalation flag.

TaskYou defineYou get back
Multi-slot policy audit4 to 10 rubric questions over one document or code diffEvery slot answered in one pass, with probabilities per slot
High-cardinality intent routing77 to 151 intents (Banking77 or CLINC150) plus an out-of-scope bucketThe chosen intent via a 2-stage bracket tournament in ~336 ms
Guardrail and drift checkInjection, toxicity, and tool-drift rules in a templateA fast exit on clear traffic (66% in our suite) or a handoff to Gemini (34%)
Listwise passage rerankingA query and 10 candidate passages on one canvasExpected relevance scores from 0 to 3 for all 10 passages in one pass, with zero ties
Visual box localizationAn image and target objects using the SigLIP vision towerBounding-box coordinates and occlusion flags in one pass

How an answer is made

Each allowed answer in a slot gets a one-token letter code from A to Z. An ordinary language model writes out one token after another. DiffusionGemma places a [MASK] token at every answer slot on a shared 256-token canvas and reads the state and all slots together in one step. At each slot position the model produces a score, called a logit, for every token in its vocabulary. We keep only the logits of the allowed letter codes, subtract the model's blank-input position habit, average the forward and reversed option lists, and turn them into probabilities with softmax so they add up to 1.

The full text of each option sits in the prompt context while the slot only predicts a single letter (A to Z). A twenty-word rule and a one-word label compete on equal terms. Nothing is sampled and no free text is parsed, so the same request gives the same answer every time.

Limits of a single pass

  • No scratchpad for arithmetic or date counting. A single pass cannot run a multi-step loop. On the 15 date and time items in JevBench, single-pass accuracy is 66.7%. Route calculation tasks through the entropy gate to Gemini.
  • It only picks from the options in your template. It cannot write a free-text summary or copy a span out of the state unless you list the candidates as options.
  • Missing context cannot be guessed away. Suppose a prompt asks if "Your package could not be delivered" is spam, but leaves out the sender address. No fixed probability can be calibrated for both a real carrier domain and a phishing feed at once. The practical fix is to list the required fields as their own check in the template; automatic missing-context detection is an open experiment (PROP-08).
  • Slots natively hold 26 letters. The letter codebook runs from A to Z. For questions with 27 to 255 options, dgem splits the list into Round-1 brackets of 20 on the first pass and runs a Round-2 final pass (section 6).
02

Try it

The quickest way is Decision Studio: dgemma.aaie.cloud. It has a live editor for the state and policy templates, probability bars and entropy readouts for every slot on the canvas, reliability diagrams, and benchmark replay tabs across our evaluation suites.

From a shell, you can run dgem against a local Apple Silicon Metal server, a Cloud Run GPU service, or the compatible POST /v1/systemone HTTP route. Here is a CLI call using a template with dual-mirror and null-prior calibration turned on:

./bin/dgem decide \
  -u "https://dgemma-uc.a.run.app/v1" --gcp-auth \
  -t templates/support_triage.json.tmpl \
  --dual-mirror --null-prior-debias \
  -v ticket="Charged twice for March. My card shows two charges of \$49 on 3/2." --format json

You can also post JSON straight to POST /v1/systemone (or POST /v1/chat/completions on port 8080):

curl -s http://localhost:8095/v1/systemone -H "Content-Type: application/json" -d '{
  "state": {"subject": "Charged twice for March", "body": "My card shows two charges of $49 on 3/2.", "plan": "Pro"},
  "questions": {
    "team":     {"type": "choice", "instructions": "Which team should own this ticket?",
                 "options": {"billing": "charges, refunds, invoices", "technical": "bugs, outages", "sales": "upgrades"}},
    "urgent":   {"type": "noul",   "instructions": "Does the customer report money already taken incorrectly?"},
    "severity": {"type": "score",  "instructions": "Rate impact severity from 0 (cosmetic) to 3 (financial loss).",
                 "scale": [0, 1, 2, 3]}
  }
}'

The server returns the chosen answer, the probabilities for every option, and the diagnostics from the single pass. Illustrative response: values are examples, and mirror_tvd is not yet returned by /v1/systemone or dgem decide (tracked as PROP-00).

03

Starting point: DiffusionGemma 26B-A4B as it comes

DiffusionGemma 26B-A4B pairs Gemma 4's mixture-of-experts weights (26 billion parameters in total, 4 billion active per token) with a bidirectional canvas. Prompted with lettered slots, the untouched base checkpoint is already an accurate zero-shot judge. It scores 88.0% raw accuracy on our 50-case public guardrail suite, 84.0% (194 of 231, upstream djev reference) on JevBench v1.3.1, and 96.0% across the standard Decision Index tasks.

Four flaws make the raw checkpoint unsafe to trust as a decision model out of the box:

  • Its raw probabilities are too confident. At temperature 1.0, 75.8% of answers on the Decision Index claim an average probability of 0.988 while only 75.2% of them are right. That gap produces a 10-bin calibration error (ECE) of 0.2388.
  • It has a strong habit of picking option A. Given a content-free state and generic options, the model puts 88.3% probability on slot A for 2 options, 78.3% for 3 options, and 49.3% for 4 options (nearly double the 25% random chance rate).
  • Option order hides 50/50 toss-ups. On contested ChaosNLI items where human raters split evenly, putting a plausible choice in slot A feeds the model's position habit. On perm_08, normalized entropy was 0.007 (99.9% for one option) even though reversing the list changed the reading substantially.
  • Canvas size limits reject wide requests. A single slot only maps 26 letters (A to Z), and the 256-token canvas overflows past 10 questions. Raw endpoints fail with HTTP 422 on 6 of the 22 Decision Index suites (a 27.3% suite failure rate).

Rather than fine-tuning a new adapter for each task, dgem fixes all four flaws in the serving and calibration layer around the frozen weights.

04

How it reads a canvas: one pass for multiple slots

On each request, dgem renders your template and state into a prompt followed by a canvas block. Every question (plus its reversed mirror copy) sits in a named slot on the canvas. The model runs one forward pass with causal attention over the state and two-way attention across the canvas slots.

1. Pre-pass (0.1 ms)
Render template; place forward (A..D) and reversed (D..A) slots on canvas
→
2. One GPU pass
Two-way canvas readout over all masked slots (~125 ms)
→
3. Tare the scale
Subtract blank-input position habit p0 in logit space
→
4. Mirror & scale
Average forward and reversed ballots; apply temperature T*
→
5. Gate
Return fast if H̃ < 0.16; escalate to Gemini if ballots clash

Steps 1, 3, 4, and 5 are CPU math and take less than 0.2 milliseconds in total.

Two serving details matter on vLLM. First, FlashAttention-2 rejects the mixed prompt-and-canvas attention mask, so dgem starts vLLM with --attention-backend TRITON_ATTN --enforce-eager. Second, conditional rules (depends_on and ask_if) split questions into level 0 and level 1 in the scheduler, which forces two sequential passes (reads=2). To keep a strict single pass (reads=1), place all slots at level 0 on the same canvas and apply conditional rules in the client after the pass finishes.

Why we keep the base weights frozen
Fine-tuning bakes a fixed training mix and a fixed class prior into a 52 GB weight file. Keeping DiffusionGemma frozen lets one container serve support triage, SecOps drift checks, 151-way intent routing, passage reranking, and visual box localization. You change behavior by editing a 20-line .json.tmpl file and passing environment base rates at request time.
05

Policies as templates: changing behavior without retraining

In dgem, a decision policy is a plain template file (templates/*.json.tmpl) stored in git with your code. Each template names the state fields to read, the slots to put on the canvas, and the criteria for each option.

  • Joint evidence and decision slots. Placing intermediate check slots (such as constraint_check and injection_detected next to final_verdict) on the same canvas lets the slots read one another during the single pass. On our 30-case multi-domain benchmark (EXP-01), multi-slot templates reached 96.7% accuracy on local Apple Silicon Metal and 93.3% on Cloud Run L4.
  • Long option descriptions cost no extra slot tokens. The full description of each choice sits in the prompt while the canvas slot only predicts a single letter (A to Z). Replacing one-word labels (["safe", "unsafe"]) with eight-word policy rules causes zero probability decay.
  • Explicit slots for missing context. If a deciding field (such as the sender domain on a delivery text) might be missing from the state, you add a context_sufficiency slot (["sufficient", "missing_sender_metadata"]) on the same canvas so the engine flags missing data instead of guessing.
06

Calibration without training: Invariant Decision Calibration

A single-pass Shannon entropy score only measures how flat the probability bars are over A, B, C, and D for one prompt. It cannot tell if the model picked A out of habit, and it cannot tell if flipping the list order would change the answer. Our calibration pipeline, called Invariant Decision Calibration (IDC), runs four steps at inference time:

  1. Null-Prior De-Biasing (Tare the Scale, --null-prior-debias). We measure the model's blank-input position habit p0(k) once for each option count K. At request time we subtract that prior in logit space: log p̃k = log pk − α log p0(k). No labeled data is needed. On our 16-item permutation suite (EXP-13B) Brier fell from 0.0173 to 0.0017 on answers that were already correct, but flips under other orderings rose from 12.5% to 25%.
  2. Single-Pass Dual-Mirror Canvas (--dual-mirror). For each question q with options [o1, …, oK], dgem puts a second slot qrev on the same canvas with the options reversed [oK, …, o1]. Both slots run in the same forward pass (124.7 ms vs 128.8 ms for one slot). Comparing them gives a live disagreement score, Mirror TVD. It only tests the reversed order, the two slots can see each other, and with the current 70/30 merge it slightly worsens Brier and ECE.
  3. Slot Temperature Scaling (--temperature-scale). Dividing logits by a scalar T* softens overconfidence without changing any top answer. On the 50-case suite ECE fell from 0.0745 to 0.0326 with T* = 1.35, but T* was fitted on the same items, so this is in-sample (held-out test: PROP-01).
  4. Wide-Canvas Batching & 2-Stage Bracket Routing. Requests with more than 8 questions are sliced into 8-slot canvas batches. Questions with 27 to 255 options are packed into 20-option Round-1 brackets on the first canvas pass, followed by a Round-2 Finals pass among the bracket winners.

Subtracting the position habit improves both accuracy and trust. Single-pass Dual-Mirror readout vs. multi-pass symmetrisation

An autoregressive model needs 2 to 4 separate forward passes (and 1.2x to 1.8x latency) to average over reversed or shifted option orders. 08

Probabilities and routing

Per-slot probabilities let you run a two-stage cascade (EXP-05) so you do not trust a fast model on hard edge cases or pay for a big model on easy traffic. For each slot m with K options, dgem computes normalized Shannon entropy H̃m = (−∑ pk ln pk) / ln K ∈ [0, 1] (and, in bench-permutation, Mirror TVD).

For requests with H̃m < 0.16, dgem returns the Stage-1 answer right away. On our 50-case public suite that fast path clears 66% of items in one GPU pass, and all 33 of them were correct. Requests with H̃m ≥ 0.16 (the other 34%) go to gemini-3.8-flash, gemini-3.7-flash, or gemini-3.5-flash-lite on Vertex AI. The cascade reaches 98.0% accuracy (49 of 50) at 56% lower cost than calling Gemini on every item. This gate uses entropy only (no IDC), and the 0.16 threshold was tuned on the same 50 items.

Two caveats apply to probabilities and routing:

  • Single-wording confidence can still miss hard phrasing flips without checks across wordings. On JevBench's 36 standard paraphrase pairs, dgem answered both wordings right on 35 of 36 pairs (97.2%). On the one pair that flipped (original-adequacy-03, checking if {"value":3} satisfies a request for a JSON array [3]), wording A gave no (right) at 0.942 probability while wording B gave yes (wrong) at 0.936 probability. Entropy on the flaky pair was 18.9% higher than on the 35 stable pairs (H̃ = 0.333 vs. 0.280), yet 0.936 probability on wording B was still too high. Putting both wordings as parallel slots on the same canvas could catch such flips in one pass; this is proposed (PROP-07), not implemented.
  • Deployment base rates must be set when class priors shift. A model calibrated on a 50/50 benchmark will flag too much spam on a corporate domain where only 0.5% of mail is spam. There is no base-rate option yet; shifting prior odds for your traffic mix (or re-estimating them from unlabeled traffic) is proposed as PROP-09.

10

What is deployed

dgem is a zero-idle-cost stack written in Go (CLI, client SDK, calibration engine, and HTTP server) paired with a small Python proxy (structured_server.py) in front of vLLM:

  • Cloud Run GPU container (dgemma). Built from deploy/cloudrun/Dockerfile and pushed to Artifact Registry (us-central1-docker.pkg.dev/$PROJECT/dgem/dgemma:latest). The 17.53 GiB weights live in GCS (gs://dgem-weights-$PROJECT/dgemma/) mounted via Cloud Storage FUSE with --safetensors-load-strategy prefetch.
  • vLLM nightly engine with Gemma 4 & Triton patch. Runs vLLM commit 133b71e0be on internal port 8000 with --attention-backend TRITON_ATTN --enforce-eager --max-model-len 32768 and our patch_vllm.py hook so vision and text weights load cleanly.
  • Structured decision server & Go gateway. structured_server.py listens on port 8080 and turns decision schemas into 256-token canvases. Above it, dgem serve and dgem bench-decision-index --serve-systemone :8095 serve POST /v1/decide and POST /v1/systemone with wide-canvas batching, bracket tournaments, null-prior calibration, and OpenTelemetry spans.
  • Decision Studio & Astro docs site. Hosted at dgemma.aaie.cloud (studio/), Decision Studio serves a browser UI for editing templates, viewing live slot probability bars, and inspecting benchmark receipts; docs-site/ builds the full experiment ledger into a static site.
11

Limits and what is next

  • Hard-tier paraphrase variance is untested (PROP-07). JevBench's 36 standard paraphrase pairs reached 97.2% agreement, but the 111 hard items have no upstream paraphrase pairs. A proposed experiment (PROP-07) will put several question wordings as parallel slots on the same canvas to measure how often rewording changes the answer.
  • Order effects beyond reversal (PROP-03, PROP-04). Testing whether the same-canvas mirror hides disagreement, and whether uncertainty signals track real human disagreement on 300+ ChaosNLI items. See docs/experiments/proposed.md.
  • Omitted variables and base-rate shifts (PROP-08, PROP-09). Testing whether uncertainty rises when a decisive field is removed, and adding base-rate adjustment for deployments whose class mix differs from the benchmark.
  • Multimodal RAM limit on L4. Turning on the SigLIP vision tower (DISABLE_MM=0) with GCS FUSE prefetch exceeds the 32 GiB host RAM limit on nvidia-l4 due to Linux page-cache copies. Vision workloads require CLOUDRUN_GPU_TYPE=nvidia-rtx-pro-6000 (80 GiB RAM).
  • Cold-start load time on scale-to-zero. Because we keep zero idle GPU instances (--min-instances=0 and teardown right after tests), the first request after a cold start waits 6 to 8 minutes while vLLM streams weights over GCS FUSE.
