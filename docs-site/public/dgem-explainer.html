dgem

Templates, one-pass readout, honest uncertainty and routing for a zero-shot decision engine on DiffusionGemma.

dgem takes some text or an image (the state) and a list of typed questions from a template file. For each question it returns the answer it picked, a probability for every allowed answer, and a hesitation score. All questions are answered together in one forward pass: about 55 ms of GPU time and 150 ms end to end on the production endpoint. We don't change the model weights. Confident answers are used directly; hesitant ones go to a person or to Gemini.

This page explains what you can build, how a decision is read, what the confidence numbers mean and what we learned testing ways to correct them. The detailed record is in the benchmark briefing; the documentation starts at the docs home.

01

What you can build

  • Triage and routing. Urgency, owning team and sentiment for a ticket, in one call.
  • Guardrails. Prompt-injection, toxicity and agent tool-drift checks as separate questions on one input.
  • Policy checks. "Does this refund meet the policy?", with a follow-up question asked only when it doesn't.
  • Reranking. Grade 10 retrieved passages side by side in one pass and quarantine poisoned ones.
  • Evaluation. A fast first-pass judge that escalates uncertain verdicts to Gemini.
  • Images. Questions about screenshots or photos, including coarse bounding boxes.

Behaviour lives in a template file (.json.tmpl) in git. Adding a question or an option is an edit, not a training job.

02

How an answer is made

Template
Typed questions: boolean, choice (≤26 options), score
→
Canvas
Each question gets a masked answer slot; options become letters A–Z
→
One forward pass
All slots are filled together and can see each other
→
Answer
Chosen option, probability of every option, hesitation

Questions that depend on another answer (depends_on) run in a second pass; questions with more than 26 options use a two-stage bracket.

Unlike a chat model, nothing is written word by word, so there is no JSON to parse and the probabilities belong to the decision itself rather than to formatting tokens.

03

Confidence

Hesitation is the entropy of an answer's probabilities, scaled to 0–100% by the number of options: 0% when one answer has all the probability, 100% for a coin toss. It makes a yes/no question and a 26-option question comparable.

HesitationMeaningWhat to do
< 16%ClearAct automatically
16–50%Somewhat unsureEscalate if errors are costly
> 50%Very unsureSend to a person or to Gemini

On JevBench, hesitation alone detects most wrong answers (AUROC ≈ 0.85). Calibration is still policy- and data-specific: check your own with Calibrate your policy.

04

What we learned trying to correct the probabilities

DiffusionGemma, like other language models, favours the first option when it is unsure: on a blank 2-option question it puts 88% on option A. We tested ways to fix that at request time (at the time called Invariant Decision Calibration; dgem now gates on hesitation and monitors order instead):

TechniqueFindingStatus
Null-prior de-biasing ("tare the scale")Improved the 50-item suite (Brier 0.147 vs 0.175–0.193) but hurt JevBench (Brier 0.293 vs 0.264)Research; validate per suite
Reversed "mirror" ballot on the same canvasLost accuracy because both slots used letters A, B, C for different options (154 vs a 182–189 band); digit labels fix that but add littleResearch
Mirror in a separate passA small extra signal, no better than reading twice; at most +0.016 AUROC for double the costResearch
Temperature scaling (held-out)Cut JevBench ECE by 24–33%; no reliable gain on the 50-item suiteOptional
Hesitation gate + Gemini cascade221/231 on JevBench with 39% escalated (Gemini alone: 225); 98% on the 50-item suite with 34% escalatedRecommended
Two lessons for template authors
Question ids are read by the model: a second slot named …mirror… cost 19 items. Use neutral, descriptive ids. And don't give two slots the same letters for different meanings.

07

Limits

  • One pass can't reason step by step. Multi-hop or arithmetic questions need the cascade.
  • Small samples. Calibration results rest on 50–231 items; check on your own data.
  • Per-item answers depend on the serving image. A vLLM upgrade changed ~5% of answers with no change in totals.
  • 26 options per question in one pass; conditional questions add a pass.
  • Long multi-slot prompts are slower (12-slot reranking took ~1.4 s on the old L4).
